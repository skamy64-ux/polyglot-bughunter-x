# Code of Conduct

Be decent. Assume the other person is trying to help.

* Critique the code, not the person. "This breaks on empty input" is useful;
  "you clearly didn't think" is not.
* Accept that people arrive with different levels of experience, and that some
  questions have already been answered in the docs.
* When you disagree with a maintainer on scope, argue about the goal rather than
  winning the thread.

That's it. There's no committee, and nobody needs to file a form.

## Security reports do not go in issues

If you found a vulnerability in *this tool* — something that lets a request reach
an unauthorized host, executes something destructive, or bypasses the payload
gate — email `security@polyglot-bughunter-x.dev` instead. See
[SECURITY.md](SECURITY.md).
